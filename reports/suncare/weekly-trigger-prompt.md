이 다이제스트는 **작성자 → 검토자** 2단계로 완성된다.

```
PHASE 1 (작성자): 뉴스 수집 → 초안 작성 → DRAFT 저장
```

# ━━━ PHASE 2: 검토자 (Reviewer) ━━━

> **지금부터 역할을 전환한다. 당신은 작성자가 아닌 독립 검토자다.**
> DRAFT를 처음 보는 편집장 관점으로 냉정하게 검토한다.

## STEP R-1. DRAFT 열람
`reports/suncare/weekly/YYYY-WXX-선케어-주간-DRAFT.md` 를 Read한다.

## STEP R-2. 검토 항목 (주간 버전)

| CHECK | 항목 | 기준 |
|-------|------|------|
| 1 | 출처 명시 | 모든 뉴스에 매체명·날짜 있는가? |
| 2 | 기업명 문장 | 기업 행위가 원본 출처에서 직접 확인된 사실인가? |
| 3 | 수치 근거 | 금액·건수·성장률에 출처가 있는가? |
| 4 | 인과관계 서술 | 원인이 출처에서 명시된 것인가? [추론] 표기 또는 삭제 |
| 5 | 금지 서술 패턴 | "~추정 / ~것으로 보임" 등 출처 없는 단정 없는가? |

각 항목을 PASS / FAIL로 판정. FAIL이면 위치와 수정 내용 기록.

## STEP R-3. 수정 적용
FAIL 항목 수정 후 해당 CHECK 재확인.

## STEP R-4. 최종 발행
모든 CHECK PASS 시:
1. 최종 파일 저장: `reports/suncare/weekly/YYYY-WXX-선케어-주간.md`
2. 파일 말미에 검토 결과 추가:
```
---
## ✅ 검토자 검토 완료
| CHECK | 항목 | 결과 |
|-------|------|------|
| 1 | 출처 명시 | ✅ PASS |
| 2 | 기업명 문장 | ✅ PASS |
| 3 | 수치 근거 | ✅ PASS |
| 4 | 인과관계 서술 | ✅ PASS |
| 5 | 금지 서술 패턴 | ✅ PASS |
```
3. DRAFT 파일 삭제
4. git add + commit (메시지: "feat: YYYY-WXX 선케어 주간 다이제스트 최종 발행")
5. push (브랜치: claude/create-kpi-planner-NmxmU)
